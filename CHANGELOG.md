# AutoInformant Pro 2.0.2

## Переназначение аудио остановок внутри `.aipack`

- В контекстном меню остановки (ПКМ) команда **«Назначить аудиофайл»** теперь предлагает два явных действия: **выбрать из активного аудиопака** или **выбрать на компьютере и импортировать в пак**.
- Для выбора из пака диалог открывается в каталоге ресурсов именно эффективного профиля: базового профиля карты или активной категории текущей модели транспорта.
- Файл, уже находящийся внутри выбранного профиля, записывается в `manifest.json` относительным путём без лишней копии.
- Файл из любого другого места копируется в `<asset_root>/_AutoInformantCustom/`, получает уникальное безопасное имя, а в `stop_overrides` сохраняется относительный путь. Кириллица в имени сохраняется.
- Файл из другого профиля того же `.aipack` также импортируется в активный профиль. Это сохраняет изоляцию категорий и не создаёт зависимости между базовой библиотекой и категорией транспорта.
- Убрано тихое сохранение внешнего абсолютного пути в `autoinformant_pro_settings.json`: если для карты/транспорта нет активного профиля `.aipack`, назначение не выполняется и приложение объясняет, как активировать пак.
- Схема `.aipack` v1, пользовательские настройки v12 и Lua-протокол v2 не менялись. Поставляемые паки не изменялись.

## Проверки 2.0.2

- Добавлены тесты импорта внешнего файла в `_AutoInformantCustom` и сохранения относительной ссылки в манифесте.
- Проверено повторное открытие установленного пака, разрешение назначенного аудио и включение файла/манифеста в экспортируемый `.aipack`.
- Проверено назначение файла, уже находящегося в активном профиле, без дублирования.
- Проверено, что при активной категории файл назначается в категорию, а не в базовый профиль карты.
- Полный набор unit-тестов: 95/95 PASS.

# AutoInformant Pro 2.0.1

## Яндекс Музыка — непрерывная «Моя волна» и более плавное воспроизведение

- Следующая партия Rotor теперь запрашивается заранее, пока звучат последние треки текущей партии. При переходе приложение сначала использует подготовленные рекомендации и не ждёт сетевого запроса после окончания пятого трека.
- Список `queue` для Rotor ведётся по всем уже полученным трекам, а не только по тем, для которых уже отправлено событие `track_started`. Это соответствует семантике API и снижает вероятность повторов при запросе новых партий.
- Для Яндекс-потока убрано искусственное ограничение FFmpeg `-re`: аудиосегменты заполняются с доступной скоростью сети, а не принудительно в реальном времени.
- Размер сегмента увеличен с 4 до 8 секунд: меньше переключений аудиофайлов и меньше работы на каждую минуту музыки.
- Для временных сегментов добавлены короткие линейные микрофейды на краях, включая внешнюю акустическую копию. Они подавляют щелчки на стыках, не затрагивая обычные аудиофайлы и объявления.
- Настройки пользователя, схема `.aipack`, локальные паки и Lua-протокол сохранены. Lua-плагин обновлять не требуется.

## Проверки 2.0.1

- Дополнены тесты Rotor: учёт всех полученных треков, передача списка исключений в следующий запрос и последовательное расширение списка между партиями.
- Добавлен тест микрофейдов PCM WAV: нулевые крайние сэмплы, сохранение центральной части и корректное сохранение формата.
- Результаты фактических проверок и ограничения среды см. в `TEST_REPORT_RU.txt`.

# AutoInformant Pro 2.0.0

## Встроенная интеграция Яндекс Музыки

- Добавлена отдельная вкладка **«Яндекс Музыка»** внутри существующего раздела «Музыка и радио».
- Добавлена OAuth Device Flow авторизация через Яндекс ID: код подтверждения, открытие страницы Яндекса, отмена входа из окна приложения. Пароль не запрашивается и не хранится приложением.
- Токен каждого пользователя сохраняется отдельно в Windows DPAPI (`%LOCALAPPDATA%\AutoInformantPro\user_data\yandex_music.dpapi`), не попадает в JSON настроек, логи, аудиопаки и дистрибутив.
- Добавлены поиск треков/исполнителей/альбомов/плейлистов, «Мне нравится», личные плейлисты, понравившиеся альбомы и исполнители, просмотр содержимого альбомов и артистов.
- Добавлены сессии «Моей волны» и режим `settingDiversity:favorite`; обработчики отправляют события начала, завершения и пропуска в Rotor.
- Добавлены ручная очередь, окно очереди, проигрывание выбранного трека, добавление в очередь, лайки треков/альбомов/исполнителей, предыдущий/следующий и стоп.
- Потоковое аудио передаётся через FFmpeg в существующий `OpenOMSIBridge` и независимый музыкальный источник openOMSI. Захват окон Windows/loopback не используется.
- Аудио делится на короткие PCM WAV-сегменты; внутренние маркеры позволяют отличить конец сегмента от конца композиции. Очередь и кэш удерживаются до подтверждения последнего сегмента игровым плагином.
- Подписанные прямые URL генерируются непосредственно перед воспроизведением и не сохраняются в настройках или логах.
- Зависимость `yandex-music==3.2.2` добавлена в `requirements.txt` и установочный запуск.

## Совместимость и известные ограничения

- Формат `.aipack` schema v1, пользовательские настройки schema v12, исходные три аудиопака и Lua-протокол v2 не менялись. **Lua-плагин обновлять ради 2.0.0 не нужно.**
- API-клиент `yandex-music` — сторонняя реализация неофициального внутреннего API Яндекс Музыки; интерфейсы сервиса могут изменяться.
- Автоматическое обновление OAuth-токена библиотекой не поддерживается; при истечении/отклонении токена пользователь проходит вход повторно.
- Если доступен только preview, UI обозначает ознакомительный фрагмент; зашифрованные raw/lossless-форматы не обходятся.
- Текущий Lua-мост не предоставляет безопасной команды Pause/Seek для этого источника; в 2.0.0 доступны Play/Stop/Previous/Next и управление очередью.
- Реальный авторизованный CDN-поток и воспроизведение в настоящем Windows/openOMSI не могли быть проверены без тестового аккаунта и запущенной игры. Автотесты покрывают адаптер и локальный FFmpeg-сегментатор.

# AutoInformant Pro 1.10.0

## Редактор категорий аудиопаков

- Добавлена полноценная рабочая страница **«Редактор категорий»**, открываемая из карточки выбранного пака через **«Управлять категориями…»**.
- Можно создавать любое количество категорий внутри профиля карты: например, «Троллейбусы», «Трамваи», «Электробусы», «Автобусы малой вместимости» или любые пользовательские названия.
- Для каждой категории можно менять название и профиль карты, импортировать собственную папку аудиофайлов, открыть папку категории для ручной работы, назначать транспорт из текущей телеметрии openOMSI, добавлять модели вручную и удалять назначения.
- Удаление категории удаляет только её собственную аудиопапку и назначения; базовая библиотека и другие категории остаются нетронутыми.
- Категория сохраняет семантику **полной замены** базовой аудиотеки для назначенной модели: нет fallback к автобусным звукам карты.
- Импорт папки копирует содержимое внутрь `.aipack` и атомарно заменяет библиотеку категории; исходная папка пользователя не изменяется. Защищено копирование пакета в самого себя и импорт символьных ссылок.

## Визуальный редизайн

- Интерфейс приведён к визуальному языку openOMSI: тёмный графитовый фон, оранжевые акценты, постоянная боковая навигация, плоские карточки и спокойная типографика.
- Убраны классические белые рамки у таблиц и полей ввода в fallback-теме Tk; разделители стали нейтральными, а системные квадратные чекбоксы заменены компактными переключателями-пилюлями.
- Настройки получили секционные карточки, единый акцентный цвет и собственные плоские слайдеры.
- В «Музыке и радио» стандартные системные вкладки заменены плоскими переключателями без белой рамки; карточки, таблицы и кнопки приведены к общей палитре.
- Редактор категорий уплотнён для экрана 1366×768: список моделей и кнопки управления категориями видны одновременно.
- Страницы «Обзор», «Аудиопаки», «Музыка и радио», «Настройки» и редактор категорий остаются внутри единого окна.

## Быстрый микшер на «Обзоре»

- Добавлены два независимых ползунка: **информатор** и **музыка/радио**.
- Иконки динамика и ноты одновременно служат кнопками Mute/Unmute. При включении восстанавливается последний ненулевой уровень каждого источника.
- Слайдеры настраивают отдельные выходные множители после существующих усилений; расширенные уровни и параметры пространственного звучания не заменяются.
- Для применения громкости без риска перезаписать play/stop-команду Python отправляет значения через отдельный `bridge_settings.json`, который Lua опрашивает независимо от очереди воспроизведения.
- Обновлён Lua-плагин до протокольной версии 2. **Для живого изменения громкости нужно один раз обновить плагин через «Обновить плагин» и перезапустить openOMSI.** Установщик автоматически делает резервную копию прежнего `main.lua`.
